# 쿠팡 판매·재고·발주 대시보드

주소: https://mcnulty-online.github.io/coupang-dashboard/sales/

## 매일 갱신하는 법

1. 쿠팡 서플라이어허브에서 아래 3개 파일을 내려받습니다.
   - 판매분석 일별 성과 (`A00046945_SALES_ANALYSIS_DAILY_PERFORMANCE_….csv`) — 최근 7일
   - 로켓 기본운영 재고 (`basic_operation_rocket_….csv`) — 최근 7일
   - 발주 SKU 리스트 (`PO_SKU_LIST_….csv`) — 최근 30일 발주분
2. GitHub 저장소에서 `sales/input` 폴더로 들어가 **Add file → Upload files**로 3개를 올리고 **Commit changes**를 누릅니다.
3. 1~2분 뒤 대시보드 주소를 새로고침하면 반영돼 있습니다. (진행 상황은 저장소 위쪽 **Actions** 탭에서 볼 수 있습니다.)

파일명은 바꾸지 말고 그대로 올려주세요. 기간이 겹쳐도 괜찮습니다. 같은 날짜는 파일명 기준 가장 최근 파일 값을 씁니다. 발주 내역(입고 예정)은 가장 최근 발주 파일 하나만 씁니다. 월별 발주금액은 발주 이력 + 올린 발주 파일 전부를 합쳐 계산합니다(같은 발주번호·SKU는 가장 최근 파일 기준).

## 계산 기준

- PPM = (매출 − 매입원가 × 1.1) ÷ 매출
- 커피/차 · 음료 구분은 세부카테고리 기준
- PMC = 판매 파일의 '쿠팡 추가 할인가' 합계
- 재고일수 = 기준일 재고 ÷ 최근 30일 일평균 판매량 (긴급 7일 미만 · 주의 14일 미만 · 과잉 90일 이상)
- 입고 예정 = 발주 확정수량 − 입고수량
- 발주 금액은 모두 VAT 제외(확정수량 × 공급가), 판매 금액(GMV)만 VAT 포함
- 당월 마감 예상 매입금액 (발주금액 VAT 제외 = 총발주 매입금 × 공급가/매입가, 입고예정일이 속한 달 기준 · 발주된 건은 모두 입고된다고 가정)
  - 예상 = 이미 발주된 이번 달 입고분 + 추가 발주 예상(리드타임 7일 안에 발주될 날 수 × 판매원가 일평균 × 직전 6개월 발주/판매 비율)
  - 자료 받은 시각 이후 그날 더 나올 발주는 시간대별 발주 비중으로 추가 발주 예상에 포함
  - '보통 ±X억'은 지난 달들을 같은 날짜 기준으로 다시 예측했을 때의 평균 오차

- 당월 발주·입고 현황(재고·발주 탭 맨 위): 납품일(입고예정일)이 이번 달인 발주 라인. 발주금액 = 확정수량 × 공급가, 입고금액 = 입고수량 × 공급가 (모두 VAT 제외). 입고는 가장 최근 발주 파일을 내려받은 시각 기준.
  - 칸: 총 발주 금액 · 예상 입고 금액(입고 금액 + 입고 예정 발주 금액) · 미납 금액(입고일 지났는데 덜 들어온 금액) · 예상 납품률(예상 입고 ÷ 총 발주)
  - 입고일이 지난 발주도 새 발주 파일에서 입고수량이 늘면 미납에서 빠지고 예상 입고에 더해짐 (같은 발주번호·SKU는 가장 최근 파일 기준)
  - 최신 발주 파일 기간(발주일) 안인데 그 파일에서 사라진 발주는 취소된 것으로 보고 뺌. 기간 밖으로 밀려난 오래된 발주는 마지막으로 본 값 유지
